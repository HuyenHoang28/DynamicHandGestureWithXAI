# Project change documentation

- Every change to code, configuration, templates, notebooks, data contracts, or runtime behavior must update an appropriate file under `docs/` in the same commit.
- The documentation entry must state what changed, why it changed, compatibility or safety implications, and the validation performed.
- For IPN symbolic/template work, append the dated entry to `docs/IPN_SYMBOLIC_POST_C_CHANGELOG_VI.md` and update the authoring playbook when the operating rules change.
- Do not stage generated result notebooks or experiment artifacts unless the user explicitly asks to version them.
